# Coordinate worker ownership and delivery

This guide covers human coordination: who owns a scope, how work overlaps, and
what to report. It does not add a claim, readiness, status, evidence-manifest or
machine admission workflow. Use the specialist guide for the operation itself:
[LOCAL_WORKSPACES.md](LOCAL_WORKSPACES.md) for allocator/checkout mechanics,
[MERGE_QUEUE_CLIENT.md](MERGE_QUEUE_CLIENT.md) for merge dispatch and observation,
[AUTHOR_PREFLIGHT.md](AUTHOR_PREFLIGHT.md) for author checks,
[PREMERGE_EVIDENCE_REVIEW.md](PREMERGE_EVIDENCE_REVIEW.md) for evidence and review,
and [ISSUE_LIFECYCLE.md](ISSUE_LIFECYCLE.md) for issue follow-through.

## Ownership and scope

The worker who starts an ordinary task owns its branch, evidence and declared
scope. Before editing, identify the actual worker, task, owned paths, overlaps,
and planned checks in the existing PR/issue conversation or assigned task. A
GitHub account, branch name, checkout, label or copied handoff does not establish
worker identity or transfer ownership. Never take, reset, overwrite or release
another worker's active workspace or evidence. For new allocations, use this
chat's actual identity and follow the supported workspace contract; a new chat or
sub-agent has its own identity. Continue a legacy allocation only to finish or
release that exact task as the current contract permits.

Coordinate with the parent/owner before expanding scope or changing a shared
artifact. Keep parallel work disjoint where practical. Reuse an existing issue or
PR for history, dependencies and remaining acceptance; ordinary engineering does
not require creating an issue solely for a merge helper. Issue links, labels and
branch prefixes are navigation, not authority. Do not claim that a machine
reservation, readiness label or work estimate authorizes work.

A role guide defines the ordinary lane, not every specifically assigned repair.
For example, an evidence-only geography researcher remains limited to its
source/evidence scope, while a specifically assigned end-to-end package owner may
follow the engineering and delivery path for that named package, alongside the
applicable geography/science contract. Neither assignment grants general write or
production authority. Follow [GEOGRAPHY_GUIDE.md](GEOGRAPHY_GUIDE.md) and
[ENGINEERING_GUIDE.md](ENGINEERING_GUIDE.md) for their distinct boundaries.

## Progress and evidence

Report useful milestones in the existing task conversation: exact owned branch and
head, what changed or was learned, checks actually run, remaining work and concrete
blockers. Distinguish source research, researched-unresolved recommendations,
technical preparation, delivered results and accepted accounting. Preserve full
original denominators, held and adverse cases, source restrictions, uncertainty,
and immutable evidence pins. A merged PR or successful test is not scientific
acceptance, production publication or permission to import data.

Batch cases only when their scientific rule and delivery path support it; keep
unresolved or blocked cases separate without withholding independently supported
work. Reuse unchanged results only after checking their exact inputs, method,
code and applicability. Do not repeat expensive source/geometry/build work without
a material changed input or acceptance need. Keep failures and actual transport,
quota or resource limits truthful; do not turn a timeout, missing tool support or
unconfirmed state into a source denial or a completed result.

Source evidence must preserve lawful access, original subjects, provenance and
all relevant contacts. Do not bypass an actual denial, transmit private locations
through an alternate representation, invent a universal source certificate, or
redact unique evidence to satisfy a workflow. Read [GEOGRAPHY_RESEARCH_ELIGIBILITY.md](GEOGRAPHY_RESEARCH_ELIGIBILITY.md)
and the applicable source contract before any import or production operation.

## Review and integration

Every PR should have a coherent scope and an exact reviewed head. Arrange a
substantive independent review by a worker distinct from the author; sharing a
GitHub account does not make authorship and review independent. Review evidence
and actual changed behavior, including important adverse outcomes and limitations.
A review comment does not grant science credit, source qualification, production
authority or issue completion.

Use the accepted native merge queue client for normal integration; do not invent a
parallel merge procedure, dispatch, test roster or observer. Reconcile the exact
canonical terminal result and resulting main before claiming delivery. Follow the
separate publication/recovery runbooks for authorized live operations; ordinary
PR work does not reserve production access. Expiry, a passing check, or the absence
of another worker's message does not prove cleanup or transfer ownership.

## Current research policy

For historical geography work, inspect accepted-main approval data, exact regional
release pins and explicit current operation authorization before acting. Boundary
research, engineering integration and authorized location-attribute imports are
distinct scopes. Use [GEOGRAPHY_RESEARCH_ELIGIBILITY.md](GEOGRAPHY_RESEARCH_ELIGIBILITY.md)
for the current approval contract and [TOP_DOWN_GEOGRAPHY_WORKFLOW.md](TOP_DOWN_GEOGRAPHY_WORKFLOW.md)
for dependency order. An open umbrella issue is not by itself a per-region import
authorization or a reason to restart completed work.
