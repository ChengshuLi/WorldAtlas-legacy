# Evidence, tests and acceptance

Select checks for the changed behavior and review the actual evidence. Tests and structural validators establish only their stated engineering predicates; they do not determine whether source evidence applies or a scientific conclusion is justified. Retain exact base/head, source/method pins, denominator, outputs and failed attempts.

## Engineering checks

Use the package/test contracts in `package.json`, `.github/package-inputs.json`, `.github/workflows/worker-merge.yml` and the trusted merge integration. The integration code provides constrained routes, not an oracle for test sufficiency. Strict `auto` is eligible when `selectedDataSelection` proves the selected-data candidate and bindings, or when the accepted integration derives and validates its fixed reviewed consumer plan for eligible inert-evidence additions through `inertEvidenceAdditions` and `reviewedTestPlan`. These route checks do not establish substantive test sufficiency. Otherwise submit an exact current-base/head `plan.request` validated by `reviewedTestPlan`, or choose `complete` when appropriate. Plan validation binds the request and derives mandatory supported consumers; the author must identify affected consumers from changed semantics, and the independent reviewer must agree the roster is sufficient. Unknown/mixed paths default to the `full` profile, but do not automatically require `complete`: an exact narrower reviewed plan is valid when independently justified. Retain all mandatory derived consumers, builds and emitted-output checks. For schema/API changes cover migrations and both existing/new consumers. For data/geography changes, preserve the complete selected bank and prove exact additions, removals, holds and no unintended reassignment against the accepted baseline.

Trusted CI authenticates the candidate commit and combined tree before checkout/execution, derives sparse inputs from the package and verification declarations, and runs the selected profile in a credential-limited environment. Missing or mismatched required inputs fail closed; recover only the exact declared inputs through the supported path. Inspect the actual run's base, head, profile, tests, inputs, build and zero-skip result; a green label alone is insufficient.

Structural checks establish only their named invariants. `scripts/validate-structure.mjs` checks structure; source/evidence validators check declared bytes, identities and ledgers; geography and native-grid checks use the exact pinned operands; emitted-output checks compare actual artifacts. Review the implemented checker and schema for current fields and command syntax. Never run candidate code as evidence unless the trusted contract explicitly authorizes it.

Use `node --test` with the test files selected by the trusted profile. For allocator startup changes, cover both the manager API and the real CLI at its checked-in `scripts/` path; assert the fetched-main commit, root `AGENTS.md` blob identity/hash and refusal behavior before reservation. For relevant changes, inspect package declaration behavior in `scripts/integration-profile.mjs`, `scripts/merge-integration.mjs` and `test/ci-checkout.test.mjs`; these are the executable contract. The complete current test set is discovered from `test/*.test.mjs`; do not treat old shard counts, run timings, disk measurements or historical CI incidents as current capacity guarantees.

## Evidence review

Independent review is by a worker distinct from the author and addresses the exact public head; see [DEVELOPMENT](DEVELOPMENT.md) for worker provenance and the PR-comment review record. Review the actual source body, path/mode/hash, immutable inputs, output bodies, accounting and source rights; use a focused independent assessment rather than repeating unchanged expensive science. Preserve full original scope, all adverse/outside outcomes and held/pending cases. A source-free proposal can recommend a finite researched-unresolved cohort only when substantial relevant research and reasonable bounded qualification attempts are demonstrated; distinguish inaccessible/unlocated from not yet attempted, timeout from denial, and unresolved from accepted.

Record only checks actually run and their exact results. If a selected sparse input is missing, use the accepted allocator with the exact commit and include scope: it resolves tree-bound selected descriptors, acquires only the unique selected OIDs in one bounded batch, verifies complete Git object bytes, and refuses if capacity or identity checks fail. `inspect` never fetches. Do not hand-fetch/copy OIDs, broaden checkout, or hydrate unrelated history to make a test pass. See [DEVELOPMENT.md](DEVELOPMENT.md) for review/merge lifecycle.
