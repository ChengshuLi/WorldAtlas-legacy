# Evidence, tests and acceptance

Select checks for the changed behavior and review the actual evidence. Tests and structural validators establish only their stated engineering predicates; they do not determine whether source evidence applies or a scientific conclusion is justified. Retain exact base/head, source/method pins, denominator, outputs and failed attempts.

## Engineering checks

Use the package/test contracts in `package.json`, `.github/package-inputs.json`, `.github/workflows/worker-merge.yml` and the trusted merge integration. The integration code provides constrained routes, not an oracle for test sufficiency. Strict `auto` is eligible when `selectedDataSelection` proves the selected-data candidate and bindings, or when the accepted integration derives and validates its fixed reviewed consumer plan for eligible inert-evidence additions through `inertEvidenceAdditions` and `reviewedTestPlan`. These route checks do not establish substantive test sufficiency. Otherwise submit an exact current-base/head `plan.request` validated by `reviewedTestPlan`, or choose `complete` when appropriate. Plan validation binds the request and derives mandatory supported consumers; the author must identify affected consumers from changed semantics, and the independent reviewer must agree the roster is sufficient. Unknown/mixed paths default to the `full` profile, but do not automatically require `complete`: an exact narrower reviewed plan is valid when independently justified. Retain all mandatory derived consumers, builds and emitted-output checks. For schema/API changes cover migrations and both existing/new consumers. For data/geography changes, preserve the complete selected bank and prove exact additions, removals, holds and no unintended reassignment against the accepted baseline.

For an unchanged PR whose diff is independently confirmed as eligible inert-evidence additions by `inertEvidenceAdditions`, and whose base has advanced, keep the authored head unchanged and request `auto`. Preparation forms a disposable candidate from current `main` plus that reviewed head and derives the fixed evidence-consumer plan bound to the resulting exact base/head pair. This avoids a source-branch merge and a stale hand-maintained plan; it does not waive the exact-head review or current checks. If the head changes, review that new head. `auto` remains fail-closed outside eligible inert evidence or the fully bound selected-data route: executable/code changes retain their required integration/full controls, and selected bank changes retain native, geography and emitted-output controls. Do not classify mixed or unknown changes as inert evidence to use this shortcut.

Trusted CI authenticates the candidate commit and combined tree before checkout/execution, derives sparse inputs from the package and verification declarations, and runs the selected profile in a credential-limited environment. Missing or mismatched required inputs fail closed; recover only the exact declared inputs through the supported path. Inspect the actual run's base, head, profile, tests, inputs, build and zero-skip result; a green label alone is insufficient.

Structural checks establish only their named invariants. `scripts/validate-structure.mjs` checks structure; source/evidence validators check declared bytes, identities and ledgers; geography and native-grid checks use the exact pinned operands; emitted-output checks compare actual artifacts. Review the implemented checker and schema for current fields and command syntax. Never run candidate code as evidence unless the trusted contract explicitly authorizes it.

Use `node --test` with the test files selected by the trusted profile. For allocator startup changes, cover both the manager API and the real CLI at its checked-in `scripts/` path; assert the fetched-main commit, root `AGENTS.md` blob identity/hash and refusal behavior before reservation. Selected-object acquisition must also cover a `GH_CONFIG_DIR`-only environment: metadata reads and the bounded Git fetch share one `gh auth token` result without logging or persisting it. For relevant changes, inspect package declaration behavior in `scripts/integration-profile.mjs`, `scripts/merge-integration.mjs` and `test/ci-checkout.test.mjs`; these are the executable contract. The complete current test set is discovered from `test/*.test.mjs`; do not treat old shard counts, run timings, disk measurements or historical CI incidents as current capacity guarantees.

For final-bank retirement changes, cover both files already listed by the prior startup index and old files authenticated only by a committed finalization receipt. Check exact-byte reuse, unknown/edited/symlink rejection, sparse and resume behavior, and that publication leaves no unindexed tracked output outside the new roster. A successful local finalizer is preparation, not the trusted old/new bank-conservation or emitted-package result.

For prepared-bank readers, verify defensive `Buffer` copying remains the default and that private stable-buffer opt-ins still check the complete byte length and digest. Exercise non-`Buffer` byte sources through their ordinary conversion path. If the accepted pin-reader body cache is discarded after bank validation, verify subsequent exact-pin reads still reacquire and revalidate the full body.

For lost allocator-capability recovery, test the real CLI and manager boundary: only the exact current worker identity and existing clean ready work slot may rotate; path/branch/current-HEAD and linked-worktree identity must match; dirty/untracked/ignored data, trust flags, symlinks, Git locks or in-progress operations refuse without changing the registry or workspace. Verify the owner-only capability file is created before atomic registry replacement, a prepared replacement can safely resume after an injected interruption, old capabilities stop working, unknown files are preserved, and no token appears in CLI output or logs. Exercise ordinary release through the exact capability-file path and verify only that file is removed after successful guarded release. Preserve all failure evidence; do not test or implement forced cleanup.

For allocator reports, exercise the actual CLI with two owners and prove output includes only the current worker's allowlisted metadata, contains no capability token, rejects a foreign `--worker` and capability-bearing options, and returns no owner rows when no current worker identity is available. Keep shared-capacity checks on `check`; do not add a registry-wide report mode.

For `operator-release`, exercise authorized manager and real CLI success paths. Require the exact approved authorization reference, separate current operator and target owner identities, one BRA and one TGO scope at most, and exact slot/path/branch/HEAD bindings. Reject a missing/stale review receipt, review not bound to the exact keeper manifest or authorization reference, owner/operator/reviewer collisions, dependent managed slots, active readers, tracked changes, ordinary untracked files, changed keeper/restoration bytes or modes, duplicate manifest paths, copies inside the workspace, and any ignored path not covered exactly once. Verify an ordinary non-forced removal, restoration from keepers if Git refuses, durable pending and terminal receipts, preserved recovery ref, and absence of capability data from output and audit. Inject failures before and after removal and confirm the target remains recoverable and the audit state is unambiguous.

## Evidence review

Independent review is by a worker distinct from the author and addresses the exact public head; see [DEVELOPMENT](DEVELOPMENT.md) for worker provenance and the PR-comment review record. Review the actual source body, path/mode/hash, immutable inputs, output bodies, accounting and source rights; use a focused independent assessment rather than repeating unchanged expensive science. Preserve full original scope, all adverse/outside outcomes and held/pending cases. A source-free proposal can recommend a finite researched-unresolved cohort only when substantial relevant research and reasonable bounded qualification attempts are demonstrated; distinguish inaccessible/unlocated from not yet attempted, timeout from denial, and unresolved from accepted.

Record only checks actually run and their exact results. If a selected sparse input is missing, use the accepted allocator with the exact commit and include scope: it resolves tree-bound selected descriptors, acquires only the unique selected OIDs in one bounded batch, verifies complete Git object bytes, and refuses if capacity or identity checks fail. `inspect` never fetches. Do not hand-fetch/copy OIDs, broaden checkout, or hydrate unrelated history to make a test pass. See [DEVELOPMENT.md](DEVELOPMENT.md) for review/merge lifecycle.
