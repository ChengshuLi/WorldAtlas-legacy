# Issue-intake guide

This role records user requests in GitHub Issues; it does not implement code, perform research/imports, deploy, merge, or edit worker campaign artifacts. Follow accepted `AGENTS.md` and [WORKER_COORDINATION.md](WORKER_COORDINATION.md) for shared procedure. The [worker entry-point index](WORKER_ENTRYPOINTS.md) links the role prompts and guides.

Before creating an issue, search open and closed issues and relevant PR discussions for duplicates. Reuse an existing issue where appropriate and preserve its evidence/completion history. Capture the user's concrete request, bounded scope, acceptance criteria, dependencies, useful evidence and actual known dates. Distinguish reported behavior from verified findings; leave full investigation to the assigned worker.

Use labels only as navigation. Link parent/child/dependency issues without duplicating acceptance, and split only at real scope or ownership boundaries. Unknown earlier dates remain unknown; record known human dates in America/Los_Angeles. Issue creation needs no branch, PR, machine claim or readiness metadata. Return the resulting issue link and the owning lane's next action.
